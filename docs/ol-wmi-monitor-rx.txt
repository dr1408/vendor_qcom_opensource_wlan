Experimental OL WMI management RX bridge
========================================
Scope: actual WMI management MPDU copies to the existing OL rx.rx monitor
callback. Not Ethernet reconstruction, not full raw data/control RX, not TX.
Reference: Onyx 9e3c693d7d4f8e626dab27e798977b888480f895 wma_sta_mon_mgmt_rx
and dp_mon_sta_coex_mgmt_rx, adapted to OL ownership rather than Wi-Fi3 rings.

Opt in at wlan module load with ol_monitor_wmi_rx=1 (default0, readonly).
No module was loaded, installed, replaced or pushed as part of this change.
Global con_mode4 is excluded even when enabled; working HTT global capture is
not mirrored. Wi-Fi3 CONFIG_LITHIUM/CONFIG_BERYLLIUM builds use no-op stubs.

Lifecycle/ownership:
- New monitor attach and callback registration invalidate capture readiness.
- Successful cfg80211 monitor-channel completion publishes frequency+epoch.
- Before retune and monitor disable, frequency cleared and epoch advanced.
- Detach unpublishes monitor under the same peer_ref_mutex used for delivery.
- RX snapshots identity+epoch before allocation; revalidates after allocation.
- Lock held through non-sleeping HDD enqueue so osif_dev cannot be detached
  between final validation and handoff. This relies on the existing
  hdd_mon_rx_packet_cbk contract: consumes on success, validation failure does
  not consume, must not sleep or reenter OL under peer_ref_mutex. Do not replace
  it with an arbitrary callback without auditing that contract/lock order.
- WMI original frame and params are untouched. Legacy mgmt_txrx processing
  still receives the original after the synchronous copy. Extracted pdev id is
  converted back to target namespace BEFORE legacy normalization. Target radio
  must match WMA_MAC_TO_PDEV_MAP(active_monitor->mac_id). The OL object is
  separately looked up as OL_TXRX_PDEV_ID=0; that is NOT the event radio ID.
  Changing monitor MAC invalidates readiness/epoch until channel is republished.
- Frequency check rejects background/offchannel scan frames. It does not
  establish the originating firmware generation for previously queued events;
  epoch checks protect host lifecycle/copy races, not firmware timestamp proof.
- Packet bounds24..4096, protocol/type, HTControl and beacon/probe-response
  fixed body validated. Radiotap reports channel, optional valid RSSI, flags0;
  does not invent TSF, captured FCS, modulation, sequence or addresses.

Diagnostics:
  VIFMGMT state ... freq=0 means disabled/transitioning.
  VIFMGMT delivered ... means handed to HDD, not proof userspace received it.
  VIFMGMT drop=event/header/pdev/channel-or-not-ready/no-monitor/allocation/
               stale-generation/callback/no-pdev
Lines are rate-limited. Read exact module-lifetime counters from
/sys/module/wlan/parameters/ol_monitor_wmi_{seen,delivered,dropped}.
seen counts calls admitted by opt-in+non-global guard; delivered counts successful
HDD handoffs, dropped counts bridge rejections. Compare deltas, not absolutes.
No events counted when disabled/global. Extraction failures before the bridge
remain normal WMI diagnostics. Zero seen while enabled suggests absent eligible
WMI events or wrong loaded build, not automatically a radiotap/parser problem.

Audit fixes included:
- Offload indications no longer selected by the experimental OL raw parser;
  retain normal offload dispatch (unknown peer alone is not raw-format proof).
- Alternate monitor callback sets pkt_type, protocol and mac_header.
- Correct dormant control subtype constants without enabling data/control TX.

Intentionally NOT silently changed:
- STA_SCAN_MON forced disconnect and reconnect policy; interface combinations.
- Missing radiotap TX-frequency transport, synthetic STA RX fallback.
- Helper DMA timeout reclamation, retry bound, in-place mode conversion.
These are separate changes; this bridge does not claim full STA/AP concurrency.
No new firmware filters or scan traffic are generated. If firmware only sends
management events during scanning, delivery may be sparse; this bridge cannot
create continuous promiscuous reception that firmware is not supplying.

Validation performed:
- Source-extracted exact set-channel/RX functions:38 host bridge cases plus6 WMA conversion cases, UBSan+
  bounds, including malformed frames, nulls, channels/pdevs, global exclusion,
  allocation failure, teardown/generation changes and callback failure.
- Exact public header syntax checked for feature off, OL feature on, Lithium
  and Beryllium stub builds. Ownership/order/offload/channel wiring assertions.
- git diff --check.
Not performed: full kernel/module compilation, lockdep, firmware/on-air or
userspace airodump validation. ASan executable could not run on host because
its shadow mapping failed; no ASan pass claimed. Tests remain local in
/tmp/creek-wmi-monitor-tests, not shipped in driver tree.

Radio-ID correction after first device test:
The first build incorrectly compared extracted event ID1 against OL DP ID0;
it rejected1085 events. This is an implementation bug, not firmware evidence.
Now WMI host->target conversion precedes validation against active monitor MAC.
No blind subtraction, no forced pdev0 relabel, no acceptance of other radios.
Conversion failure/unknown ID rejects only the optional copy; normal RX remains.
The initial no-disruption aireplay observation is independent of capture success;
no OTA capture in that run establishes absence/cause of prior disruptive frames.

2026-11-15 RX crash audit (native-parser stabilization)
-----------------------------------------------------
Captured at uptime 623.483: unknown peer 39, offload=0, count=1 was
explicitly routed into htt_rx_mon_amsdu_rx_in_order_pop_ll(), followed
by an address-marking assertion in htt_rx_paddr_unmark_high_bits().
The old %pK error can redact a nonzero DMA address: literal zero is
NOT established. The truncated stack does not identify the first entry
versus a continuation entry as the failing read.

Onyx dp_rx_mon.c shared/unknown helpers run after native DMA unmapping
and validate TLV/decapsulation/header/binding state before copying. Its
Wi-Fi 3.0 descriptors cannot be used as OL descriptors. The examined
Beryllium 659e3f3 ol_rx.c adds a self-peer fallback, not Creek's explicit
per-indication monitor-parser override. Its synthesized STA Ethernet
mirror is not evidence of real over-the-air raw handshake reception.

Remove that override and peer substitution. Always use the parser
selected by htt_rx_attach(). Global con_mode=4 retains its stock monitor
parser; TX and WMI management-copy code are unchanged. Secondary-VIF
unknown/self-monitor buffers are consumed/unmapped by native parsing,
replenished and freed, not forwarded to STA or mislabelled as radiotap.
THIS IS NOT A COMPLETE SECONDARY-VIF RAW DATA/EAPOL BRIDGE. Management
capture remains available through WMI; raw data support remains pending.

Rate-limited VIFRX diagnostics:
- native-pop-enter: peer/TID, message length/count, header words,
  offload argument versus header bit, fragment bit, first entry words.
- malformed-native-indication: bounded non-offload envelope rejection.
- native-pop-exit: status, consumed count, head/tail presence.
- native-drop: consumed buffers reclaimed; no validated raw bridge.
- bad-dma-marker: actual DMA high/low words, expected marker and width,
  before the ORIGINAL assertion (not disabled).
Snapshots are bounded and do not dump Wi-Fi payloads. If the native
parser also asserts, compare raw entry words/flags and the new marker
line; do not infer that the parser override was the sole defect.

Host checks cover dispatch contracts/classification and bounded snapshot
copying with UBSan/bounds. A full workflow build and device regression
(global capture, normal injection, VIF management capture) are required.
